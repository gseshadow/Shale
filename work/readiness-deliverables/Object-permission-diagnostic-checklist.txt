  catalog/change record; an old ordinal alone cannot prove historical identity.
- SQL computes COUNT_BIG(*) OVER() over the same fn_my_permissions invocation as
  its detail rows, before DataTable.Load. SqlResultCount is repeated on each row;
  it is not summed. An empty result is reported as zero. Separate SQL window counts
  retain permission-name and complete entity/subentity/name tuple multiplicities.
  There is no SQL DISTINCT/GROUP BY, join or PowerShell filtering of the result.

  uses exactly Permission-List's Rows | ForEach-Object {$_.Permission} projection.
  SQL_ROW compares SQL multiplicities with counts from DataTable/projected names.
  A count disagreement stays visible and produces exit 2, never acceptance.
